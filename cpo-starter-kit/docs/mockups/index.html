Ampleaf polish: mockups

Static, clickable mockups for owner review (SQD-80). Nothing here is built into the template: pick what you want and build work is filed per screen. Every screen shows the current screen beside the proposal, desktop 1440 and phone 390, light and dark, with what changes, which Squid screen it follows, accessibility, brand tokens and a rough build size. All names, ids and figures are invented demo data.

Design rules used across every screen

  • Shell: grouped sidebar (Menu and five tabs on a phone), breadcrumbs, one page width (--content-max), one primary action per page header.
  • Tables: sticky header, numbers right-aligned in tabular figures, sortable heads with aria-sort, filter bar above, one row density, an empty state with a next step; on a phone rows stack.
  • Status: one chip set (shape + word + colour): Charging, Available, Offline, Faulted, Idle. Never colour alone.
  • Forms: label above, help beneath, inline error beside the field with text, a visible “Saved” state.
  • Detail pages: summary strip first, tabs beneath, destructive actions in their own bordered zone at the bottom.
  • Ampleaf stays Ampleaf: palette v2, Manrope and Fraunces, Lucide icons and the leaf corner. Every colour, size and radius is read from brand/tokens.css, so an operator's rebrand carries through.
